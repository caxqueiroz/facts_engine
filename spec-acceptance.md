# Specification acceptance evidence

This index maps the acceptance criteria in [spec.md](spec.md#acceptance-criteria-and-delivery-sequence) to the repository tests that exercise them. It records code-level evidence, not production approval. The race-enabled integration suite uses disposable PostgreSQL, OpenFGA and CortexDB fixtures; run it with `sh scripts/ci-integration.sh`.

## Production sign-off still required

Repository tests cannot provide the following evidence:

| Owner | Required production evidence |
| --- | --- |
| Domain/application | Versioned schemas, acceptance/review policies, principals, source classes and consuming-application validation. |
| Model/provider | Approved endpoints and model identities, data-processing approval, domain-grounded evaluation results and cost/resource limits. |
| Identity/security | Identity-to-tenant mapping, gateway/session and delegated-user trust, authorization rollout, certificate lifecycle, and managed signing/encryption key custody and recovery. |
| Retention/legal | Purpose and retention schedules, legal holds, and validated deletion coverage for derivatives, indexes, caches, object versions, archives and backups. |
| Archive/infrastructure | Separately administered immutable storage, signing keys, head/gap monitoring and object-version retention. |
| Operations | Provisioned services, telemetry collection and alerts, approved capacity/latency/RPO/RTO targets, workload benchmarks, and ledger/evidence/key restore plus search-rebuild drills. |

The repository's local workload benchmark is a diagnostic only. A production capacity decision must use approved tenant counts, corpus sizes, read/write mix, connection limits, network topology and per-tenant append-lock contention.
